# GATE-PLN-ANN-001 — Worked Example

This example shows two passing shapes: a file with proper `@planner:` annotations,
and a plan-side waiver for a file that genuinely doesn't need annotations.

## Shape 1: file with annotations

A new file `scripts/lib/sample_helper.mjs` with the minimum required annotations:

```javascript
// sample_helper.mjs — minimal annotation example.
//
// @planner:module = sample_helper
// @planner:capability = sample_helper_demo
// @planner:story_id = US-091

export function sampleHelper(input) {
  return String(input).trim();
}
```

`@planner:capability` is required at minimum; `@planner:module` and
`@planner:story_id` are commonly paired with it. Annotation_parser recognizes
14 keys total — see `references/file-formats.md` for the full list.

## Shape 2: plan-side waiver

For files that genuinely should NOT carry annotations (test fixtures,
generated code, vendored third-party files), declare a waiver in plan.md:

```markdown
## Notes

[KB_NOT_APPLICABLE: annotation: tests/fixtures/sample_plan_dir.md: fixture file consumed by test_repair_packet; not project code]
[KB_NOT_APPLICABLE: annotation: src/generated/protobuf_types.ts: generated by protoc; do not edit]
```

The `<reason>` must be substantive. `TBD`, `[FILL: ...]`, `<placeholder>`,
or `reason here` all FAIL the gate even though the waiver line is present.
